# Codex Pulse：全功能保全与前端优化执行方案

日期：2026-11-06。当前安装/发布版仍为 v0.2.0；[46组审计](FEATURE_PARITY.zh-CN.md)的2完整、27部分、17未实现是历史基准，本方案没有把计划改记为完成。

## 交付目标

原 Codex Usage Desktop 5.6.0 的46组实际能力全部有正式入口、完整数据链和验收记录，同时继续使用我们自己的品牌、清爽/刻度皮肤、独立悬浮窗、可关闭动效与F盘存储。功能不能因换皮肤、收窄窗口或开启紧凑模式而消失。

账号或第三方确实不提供的字段应显示未提供，保留查询、状态解释和恢复路径；接口存在不等于本机账号一定有值。逐项验收区分“功能可用”和“当前数据可得”，不能编造余额、价格、额度、公告或预测。

## 先确定完整引擎，再连接新界面

现版扫描器只保存Token统计，已经丢弃会话正文/来源路径/代理关联等信息。许多缺口来自这个数据模型，继续仅在现有简化snapshot上加组件无法达到目标。

上游MIT源码可在保留原版权、许可和来源的前提下复用成熟引擎。技术栈不是用户约束；避免为了保住旧外壳重复实现完整领域逻辑。

**优先验证的路线：** 保留上游Rust/Tauri成熟数据与桌面能力，接入/适配我们自己的React界面、双皮肤及悬浮窗。保留原统计、回放、采样、价格、重置服务、缓存与导出等模块的语义和测试；界面组件是否复用按功能和设计质量决定，并保留来源记录。不是仅改名后宣称全部工作完成。

**备选路线：** 若桌面迁移无法满足F盘便携、悬浮窗或发布约束，再将独立Rust核心接入现Electron外壳。该路线需实现并发通信、取消、进程退出、26个数据命令以及新的宿主能力，不宣称它天然成本更低。

在正式迁移前必须做一个独立可运行验证：

1. 使用固定上游提交构建Windows程序；依赖、编译产物和临时文件写F盘，不修改现安装程序。
2. 新品牌和独立应用数据路径；数据库、日志、缓存、WebView用户数据和临时文件均验证在F盘，不能沿用上游默认C盘app-data。
3. 只用合成日志验证自然日日均、完整月份、同名不同路径项目、跨日/模型会话、子代理和压缩日志。
4. 主窗口、托盘、独立悬浮窗的启动、隐藏、退出与重启均能运行；双皮肤/动效关闭可持久化，原安装不受影响。
5. 去除上游更新统计上报，更新源/品牌/图标指向Pulse；不保留可将Pulse更新回原程序的端点或签名配置。

以上是技术选型门槛，目前未标为通过。结论和证据写入后才扩大迁移。

## 前端如何继续优化

沿用已接受的Clear和Meter，不新增一轮风格方向选择。先把信息安排清楚，再优化字重、密度、图表、反馈和可选动效；两套皮肤共用数据、业务状态和操作组件，差异集中在布局表达、颜色与强调方式。

| 页面 | 主任务与新增落点 | 设计验收重点 |
|---|---|---|
| 仪表盘 | 范围费用/Token与来源、三维成本排行、完整范围费用/额度趋势；账号侧区；下方重置摘要/信号与Feed | 指标有主次，少用重复卡片；账户与本地统计分开标注；图例/悬停/全屏可用；长范围可明确聚合/定位，不偷偷截天数 |
| 会话 | 日期与代理层级列表，完整概要；内容/raw两类阅读，工具与补丁按需展开；搜索/回合定位；Credits独立标记 | 双栏宽度可调；长文本不挤坏布局；复制/展开/定位有反馈；切代理保留上下文；内容不执行 |
| 模型 | 用量/价格目录切换；分项、费用、单价、采样估计与不确定性；搜索/供应商/排序/分页 | 表头、单位和排序清晰；未知/免费/不可用可区分；目录操作不挤进首页 |
| 按日 | 可排序明细、星期/分项/费用/额度；峰值与连续空日；点日进入对应会话 | 数字按列对齐，横向内容保留；空日折叠可还原；点行和复制等操作不冲突 |
| 按月 | 当前月截至今天，前11个月独立自然月；环比、分项/费用/额度、排序与空月 | 不受日范围截断；留存不足、未知和零活动分开；前月为零/未知时环比文案准确 |
| 项目 | 路径/项目引用、可排序并排比较；详情趋势与定向重扫；按日会话 | 同名项目可区分；长路径可查看/复制；当前项目保持可见，趋势覆盖所选范围 |
| 设置/维护 | 外观、语言、来源、托盘、刷新、导出、缓存/诊断、更新分组 | 常用项先出现；深层项直接可达；保存失败可恢复；不以超大皮肤预览挤走维护选项 |
| 托盘信息弹出板与独立悬浮窗 | 各自呈现今日Token与费用、双窗口/倒计时、快捷打开和状态 | Windows tooltip、托盘信息弹出板与独立widget分别验证，不互相抵扣；拖动不抢按钮；多屏位置持久化；动效关闭可操作 |

导航保留六个清晰入口，并补侧栏折叠/调宽/持久化和设置返回。具体采用侧栏或可切换导航布局，要在原生工作区验证信息密度与使用习惯后确定，不能因参考软件有侧栏便直接照搬其视觉。

视觉检查覆盖两皮肤、浅/深、正常/紧凑、动效关闭、窄窗口和长内容。每个主页面、价格目录、会话详情、设置和悬浮窗均交付对应的实际运行截图；公开截图使用合成数据。

切换皮肤、颜色、密度或动效时，保留路由、日期范围/选日、所选线程/代理、搜索、排序和阅读位置；不触发扫描或账号查询。所有内容与操作在动效关闭时完整保留。这些是每批共同回归条件。

## 外部来源与交互边界

- 账号元数据/Credits/reset credits和逐会话Credits需要独立服务链；现有app-server两个read方法并未覆盖全部字段。保留可用身份与缺字段状态，凭证由本机主进程管理，不进入前端、诊断导出或公开仓库。
- Credits生命周期扣除与所选日期API估价是两种指标；保留十进制精确值、未知/缓存/部分/负数调整状态和可关闭查询。
- 逐会话Credits默认关闭且零请求；启用后只查已展开/当前详情的真实线程ID，不发送正文。关闭或切账号停止后续批；401仅重新读本机身份一次，403停自动重试，429尊重冷却；不能使用现导入缓存中哈希后的ID。
- 历史额度估算需要日志的rate-limit快照、采样/排除重叠和置信边界，不能把当下额度按Token份额摊回过去。
- 启动窗口会真实调用模型，只在明确点击和确认后执行；定时刷新、打开软件、切换皮肤均不能触发。
- 公告/预测/Feed必须显示来源和时效；第三方不可用时保留旧数据并标陈旧，预测无依据时显示无信号。
- 更新需自己的发布源、可信自有签名验证和包摘要；验证拒绝错误签名、品牌或平台。不能用上游更新配置，也不能用只有仓库链接的页面冒充安装更新完成。

上游原逻辑也须复核：CLI进程成功结束只代表请求完成，不等于额度窗口已激活；订阅必须匹配当前工作区，不能随意取其他entitlement；响应body中的敏感信息不能直接写入日志；未知价格的数值/状态必须同时传递，不能把未知总成本变成免费。

## 完成标准与发布规则

每组关闭须记录：正式可达入口、完整数据和单位、正常操作、缺字段/空内容、加载/超时/失败保留、必要的边界样本，以及两皮肤下的交互结果。适用的组另需文件/网络/安装回归，源码/截图/测试各自只能证明其覆盖范围。

外部依赖的验收另记 `testMode`（fixture/live）、实际返回字段、检查时间、数据可用状态（supported/partial/forbidden/unavailable），分别记录代码实现与当前环境联通。HTTP200或合成样本通过都不能替代真实字段核实；激活自动化只用fake CLI，真实模型调用仍由页面显式确认。

内部开发版允许分批验证，报告明确剩余项；“全功能版”只有在46组均完成适用验收后才能发布为完成。若服务或测试环境不满足，标记具体未验项并继续处理，不能以空字段兜底或一组泛化测试把整组关闭。

GitHub同步功能源码、许可证/归属、更新后的真实覆盖表、实际截图、发布说明和安装包。README中的功能声明必须与本次正式包一致，不能提前宣传未交付能力。
