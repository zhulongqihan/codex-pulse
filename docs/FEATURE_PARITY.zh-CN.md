# Codex Pulse v0.2.0 与 Codex Usage Desktop 5.6.0 功能对照

核对日期：2026-11-06。**结论：没有达到一比一；“原软件每个功能都保留”的要求尚未完成。** 两套皮肤、六个主视图和已通过的测试，均不能作为功能齐全的证明。

## 核对对象与判定方法

- 原软件：本机 `F:/codex++/UsageTools/Codex-Usage-Desktop/codex-usage-desktop.exe`，ProductVersion/FileVersion 均为 **5.6.0**。对照其公开源码 [app-v5.6.0 / 1e8d2a2](https://github.com/itvincent-git/codex-usage-desktop/tree/1e8d2a2bae8ed466b0a48a37eb16f936629aa9c0)，不借用更新版本的功能。
- 我们的软件：**Codex Pulse v0.2.0**，正式源码提交 [d45ee79](https://github.com/zhulongqihan/codex-pulse/tree/d45ee79e384e1075e24ba272a192b2885a220f8e)，安装目录 `F:/codex++/CodexPulseApp`。本次未变更运行代码或安装包。
- 从用户截图扩展到原软件实际页面、组件、数据接口与扫描链路核对。原需求清单的 46 个编号保留，旧 v0.1 状态全部重审，原清单中扩大描述的子项已纠正。
- **已实现**：该组经纠正后的原有子项在正式入口和数据链中齐备。**部分实现**：存在可用子项，但还有缺失或语义差异，整组不算通过。**未实现**：尚无对应可达功能链。
- 演示数据、原型、未挂载的旧页面、仅存在于接口的字段、CSS类名、可以计算但没有展示的值，均不计作正式交付。

严格按组统计：**已实现 2 组，部分实现 27 组，未实现 17 组，共 46 组。** 组内大小与工作量不同，这不是“完成率”；也不表示现有软件只有两个单独功能可用。

## 不同于功能缺失的统计语义问题

1. **日均分母不同。** 选7天、只有2天各100 Token时，现版“日均”为100，原软件自然日日均约28.57。这是合成例说明源码公式，不是用户用量。
2. **图表范围被截短。** 首页只画最后7个有记录日，项目只画最后14个，不能代表长范围全部趋势；日表比例还可能取错峰值基准。
3. **月份被选定范围截断。** 有月标签但没有独立完整自然月数据源，无法据此比较正常环比。
4. **会话分段不是完整会话。** 同一线程跨日期、模型或项目时生成多行；首条Token记录不是会话起点，也无法由此推算完整持续时间。
5. **项目标识丢失。** 以末级目录名分组，可能合并不同路径下的同名项目。
6. **长期窗口被统称周。** 月时长记录能被保留，但标签错误；当前剩余额度也不能代替历史每日/会话额度消耗。

这些问题需要修改数据模型、查询口径和状态传播，再连接新UI；补按钮或改CSS无法解决。

## 对旧需求清单的事实纠偏

- 原首页成本榜没有点击跳转；不把它算作缺口。Pulse的项目Token榜跳转是已有额外能力。
- 原项目分析响应有models字段，但项目弹层没有独立模型分布图；不因该字段而扩大原UI功能。
- 原主会话页没有标题搜索或默认分页；项目弹层才有搜索/代理组更多。更多日期是扩大日期范围，而非使用未启用的API游标。
- 原账号UI只在明确关闭续订时显示提示，没有续订三态控件。原侧栏也没有直接显示所有接口百分比/分钟字段，不把未展示的字段全部列为缺口。
- 原“最近重置”卡优先取常规重置；历史中再打开原文。Feed帖子时间与可选证据更新时间应区分。
- 原macOS托盘标题与Windows tooltip不能混称。原版手动时区选择和系统休眠原生监听没有被核实，不凭旧清单要求它们。

## 验证范围与后续验收顺序

本次核对的是正式源码、入口、IPC和数据流，并用自造数据验证了月窗口标签、同名项目合并、会话分段等结论；没有读取认证文件、真实会话正文或私人数据库，也没有发起模型请求。源码缺少的链路可据此判定未实现；依赖账号/第三方实际返回的能力，后续仍需明确的运行验收，不能编造账号字段。

上轮发布记录中的42项测试、12项渲染检查、双皮肤及安装包检查，只证明已经编写的部分功能通过其检查，**不覆盖这46组完整对等验收**。本次未重新跑这些无变更测试，也未发布新版安装包。审计与后续实施计划作为文档同步到源码仓库。

建议补齐顺序：先修统计口径/身份/来源模型；再补账号与重置、价格与导出；随后建立完整会话/代理/回放链；最后完成维护/更新/兼容和各页交互。每个编号必须有可达操作、真实数据、未知/失败状态及相应验证才关闭。清爽/刻度两版、可关闭动效、独立悬浮窗与F盘存储要求继续保留。

完整保全的要求早已提出，v0.2.0把界面与发布作为阶段交付，没有完成这些功能。后续应以本清单逐组验收，而不是继续把外观完成视为软件完成。
